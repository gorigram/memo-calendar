# ゴレンダー — 予定メモ

iPhoneを主な利用端末として設計した、日本語のスケジュール管理PWAです。画面を開くと入力欄が見え、メモを入力すると予定の候補を表示します。内容を確認して「予定を追加」を押すと保存します。未ログイン時はこの端末に、ログイン時はアカウントに保存します。

公開プレビュー: [ゴレンダー](https://memo-calendar-glass.maponaru0519.workers.dev) · ソース: [github.com/gorigram/memo-calendar](https://github.com/gorigram/memo-calendar)

複数の曜日を含むメモは日付ごとの予定候補に展開し、件数と全候補をプレビューに表示します。保存は自動で行わず、確認後に「予定を追加」を押します。よく使う予定は名前付きテンプレートとして最大20件登録でき、入力中の予定から名前で呼び出せます。登録内容は未ログイン時はこの端末に、ログイン時はアカウントに保存します。クラウドのまとめ追加は一括で保存し、Google Calendar同期の失敗は予定ごとに確認して再同期できます。

## 技術構成

- UIはWorkerが返すHTML、CSS、JavaScriptです。アプリ画面は外部UIパッケージを実行時に読み込まず、WorkerのESM配信とオフライン起動に合わせています。
- `worker/parser.js` は決定的な日本語ルール解析を実装します。ブラウザ内の候補表示とWorker APIの規則ベース解析で共用し、IANAタイムゾーンを使って時刻を解決します。
- 予定とタスクを分けて入力できます。予定は従来どおり開始時刻が必要で、タスクは日付が必須、時刻は任意です。タスク解析は外部AIへ送らないルールベース処理です。
- Cloudflare Workerが同一オリジンのAPI、PWA manifest、Service Worker、アイコンを配信します。公開Workerへデプロイ済みです。Service Workerは画面シェルのみをキャッシュし、API応答はキャッシュしません。
- 予定は最初にブラウザの`localStorage`へ保存します。Google認証後はD1を使い、端末のみの予定とクラウドの予定を区別して表示します。
- 公開WorkerにはD1 (`DB`) とWorkers AI (`AI`) のbindingを設定しています。D1はGoogle接続後の予定保存に使い、AIは任意の補助解析に使います。外部AIプロバイダーのAPIキーは不要です。AIを使えない場合もルール解析とローカル保存が動きます。
- Google Calendarへの自動同期は、Google接続後に設定でオンにした場合だけ実行します。同期結果が失敗や一部失敗なら画面にその状態を残します。
- Google Calendarにすでにある予定は、表示中の週を都度読み込んで一緒に表示します。読み込んだ予定はGoogle Calendar側のデータを参照するだけで、編集・削除はGoogle Calendarで行います。繰り返し予定は対象期間内の各回を読み込みます。

## メモ解析

- 日付を省略すると、端末タイムゾーンの今日として扱います。
- 開始時刻が必要です。開始時刻が見つからない、日付や時刻が矛盾する、相対日付が曖昧な場合は候補を作成しません。
- 終了時刻・所要時間を省略すると1時間です。所要時間、時間範囲、「午後3時半」などを指定できます。「1100」は11:00として扱い、終了時刻を含む時間範囲にも使えます。「明日 1800-2000 バイト」は18:00–20:00として解釈します。
- 「来週火曜」は月曜始まりの週で解決します。「来週月」のような短い漢字1字の曜日も使えます。修飾のない曜日1字は今日以降の次回として解決し、今日と同じ曜日なら今日です。「来週」だけなど日付を確定できない表現は確認を求めます。
- 「毎週」「毎日」「毎月」の繰り返しを保持します。週表示では繰り返し予定に`#1`、`#2`と回数を付けます。
- 1つのメモに複数の年月日と時刻をそれぞれ書けます。たとえば「10/29 10:00と11/5 14:00 ワンキャリア」は、同じタイトルの2件に分けて候補表示・一括保存します。全角数字や区切り記号も扱い、日付と時刻の組は入力順に対応づけます。2件目など一部に日付・時刻の不足や不正があれば、先行分だけを保存せず全件の確認を求めます。
- 保存したテンプレートは丸数字に加えて、名前でも呼び出せます。たとえば「バイト早番」は日付と一緒に入力し、テンプレートに登録した時刻・所要時間を使います。複数行の予定メモは行ごとに解析し、途中に不正な行があれば一部だけを保存しません。旧形式の丸数字テンプレートは読み込み時に書き換えず、既存の丸数字呼び出しも利用できます。テンプレートを編集した場合は保存操作で変更を反映します。

規則解析は日本語の主要な日付・時刻表現に合わせた軽量実装です。自由な文章のすべてを解釈するものではなく、判断が安全でない場合は入力を修正できるようにします。

## タスク

タスクには日付が必要です。年月日のほか、「明日」「来週の火曜」など日付を特定できる表現を使えます。時刻は省略でき、時刻を省略したタスクも期限日とともに一覧に表示します。タスクは予定とは別の種類として保存され、完了・編集・削除ができます。未ログイン時はこのブラウザーに、ログイン時はユーザーごとのD1領域に保存します。タスクはGoogle Calendarへ作成・同期しません。Google Calendar連携の自動同期設定がオンでも、タスクがカレンダーに送られないようWorker側でも制限します。

タスク対応の加算型migration `migrations/0002_tasks.sql` を本番D1へ適用し、追加した4列とmigration記録を確認しました。Worker version `0e5299f9-f4ae-4092-92db-9107e9fd0050` を公開済みです。個人Googleアカウントを使い、タスクの作成・完了・編集・削除・取り消しと、再読み込み後の保持を確認しました。QA用タスクを削除後に再読み込みし、テストタスクが残っていないことも確認しています。タスクはアプリ内だけで管理し、Google TasksやGoogle Calendarへは送信しません。

番号メモと一括予定用の加算型migration `migrations/0003_templates_batches.sql` は本番D1に適用済みです。migration履歴は維持したまま加算しています。名前付きテンプレートと複数行入力を含むWorker version `8bf4f19c-697e-41a6-b2eb-1ab6df14c45e` を公開済みです。現行ソースのNodeテスト78件、build、artifact検査、diff検査が通過しました。

【過去のブラウザーQA】Workers AIを使ったタイトル整理は本番で確認済みです。AIは予定タイトルの補助に使い、日付・開始時刻・終了時刻はルール解析と検証で決めます。試験は作成者の個人アカウントで行っており、複数利用者での運用確認ではありません。2026年10月の旧版では、ブラウザーの1280px幅デスクトップ表示と390×844 CSSピクセルの固定フレーム表示を確認し、旧版の自動追加動作も試しました。iPhone実機Safariでの表示やホーム画面追加は未検証です。D1とWorkers AIのbindingは公開Workerに設定済みです。

Google Calendarの既存予定は、表示中の週をGoogle Calendar APIから都度取得します。D1へ複製せず、読み込んだ予定はアプリ内で読み取り専用です。Google側で編集・削除した結果は次の読み込み時に反映し、Google Calendarの繰り返し予定は各回として表示します。アプリからGoogleへ同期した予定は二重表示を避け、リンク済みの単発予定はGoogle側の最新内容を表示します。アプリ作成の繰り返し予定に対するGoogle側の個別回例外は、現在アプリ内の繰り返し表示へ反映されない場合があります。Google側での外部予定の更新、終日表示、削除、翌週の重複回避を本番QAで確認しました。

複数の日付・時刻ペアを1つのメモから作る機能は、ローカルプレビューで「10/29 10:00と11/5 14:00 ワンキャリア」を2件の予定として解析し、両方を保存できることを確認しました。全角日本語の入力と逆順のペアも対応し、2つ目の日付・時刻が不完全な場合は「追加」を無効にして部分保存を防ぎます。本番では今回の入力で生じた誤登録を整理し、再読み込み後も目的の2件が各1件ずつ表示されること、新規登録分のGoogle Calendar同期完了を確認しました。検索結果から自分の予定を直接編集でき、編集画面から削除確認・取り消しの操作へ進めます。Google由来の読み取り専用予定は該当週へ移動します。

2026年11月1日の本番QAで、既存の3件の「バイト」テンプレート（17:00、21:00、17:00）を読みやすい名前で表示し、元の3件を保持しました。名前付きテンプレート2件を追加して再読み込み後の保持を確認しました。チップを押すとカーソル位置に呼び出し名を挿入し、既存の改行を保つことも確認しました。2件のテンプレート呼び出しと通常の予定1件を複数行で入力し、待機中は保存されず、「予定を追加」を押すと3件が保存・Google Calendar同期されることを確認しました。再読み込み後、3件の予定が正しい日時で表示されました。追加したQA予定3件とテンプレート2件は通常の削除操作で削除し、再読み込み後の予定検索は0件、元のテンプレート3件は保持されていることを確認しました。ローカルQAで、旧自動追加設定が有効でも自動保存されず、Ctrl+Enterでも保存されないこと、2行目が不正な入力では追加ボタンが無効になることも確認しました。1100や1100から1230の時刻範囲、短い漢字曜日を含む解析を確認しました。ローカルのモバイルハーネスは390×844、document/body幅375pxで横はみ出しなしです。スクリーンショットは作業記録`outputs/ブラウザテスト.md`を参照してください。

Google OAuthは`External / Testing`モードで、現在は指定したテストユーザーだけが接続できます。Googleのテストモードでは、基本プロフィール以外のスコープを含む認可のrefresh tokenは7日で期限切れになるため、期限後は再接続が必要です。[Google OAuthのテストモードとrefresh token](https://developers.google.com/identity/protocols/oauth2/) · [OAuthアプリのテストユーザー設定](https://support.google.com/cloud/answer/15549945?hl=en)。WebアプリとGitHubのソースは公開していますが、Googleログインは一般公開ではありません。一般利用者へOAuthを提供する前に、Google側の公開設定やプライバシーポリシーなどを整え、利用範囲に応じた審査要件に従います。独自ドメインなども、その要件に合わせて準備します。
